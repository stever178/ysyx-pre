
不想显式释放内存又能避免内存泄露的办法是引入libGC库。你需要把所有的malloc换成GC_malloc，然后把所有的free删掉。

## 1. 安装libGC库
```shell
sudo apt-get install libgc-dev
```

## 2. 基本使用示例
```C
#include <stdio.h>
#include <gc.h>  // 注意：不是 <stdlib.h>

int main() {
    // 1. 初始化垃圾回收器（可选，但推荐）
    GC_INIT();
    
    // 2. 使用 GC_malloc 替代 malloc
    int *arr = (int *)GC_malloc(10 * sizeof(int));
    
    // 3. 使用 GC_malloc_atomic 分配不包含指针的内存（更快）
    char *str = (char *)GC_malloc_atomic(100 * sizeof(char));
    
    // 4. 使用 GC_realloc 替代 realloc
    arr = (int *)GC_realloc(arr, 20 * sizeof(int));
    
    // 5. 使用 GC_strdup 替代 strdup
    char *copy = GC_strdup("Hello, GC!");
    
    // 6. 使用 GC_malloc_uncollectable 分配不会被回收的内存
    // （用于需要手动管理的情况）
    void *persistent = GC_malloc_uncollectable(1024);
    // 当确定不再需要时，可以手动释放
    GC_free(persistent);
    
    // 7. 重要：不要调用 free()！
    // free(arr);  // ❌ 错误！不要这样做
    
    // 8. 可以显式触发垃圾回收（通常不需要）
    // GC_gcollect();
    
    printf("Allocated %zu bytes\n", GC_get_heap_size());
    printf("Free bytes: %zu\n", GC_get_free_bytes());
    
    return 0;
}
```

## 3. 编译时链接库
```shell
# Linux/macOS
gcc -o program program.c -lgc

# 如果需要调试信息
gcc -o program program.c -lgc -DGC_DEBUG

# 更详细的调试
gcc -o program program.c -lgc -DGC_DEBUG -DKEEP_BACK_PTRS
```

## 4. 与现有代码集成
```c
// myalloc.h
#ifdef USE_GC
    #include <gc.h>
    #define MALLOC(size) GC_malloc(size)
    #define CALLOC(nmemb, size) GC_malloc((nmemb) * (size))
    #define REALLOC(ptr, size) GC_realloc(ptr, size)
    #define STRDUP(str) GC_strdup(str)
    #define FREE(ptr)  // 什么也不做
#else
    #include <stdlib.h>
    #include <string.h>
    #define MALLOC(size) malloc(size)
    #define CALLOC(nmemb, size) calloc(nmemb, size)
    #define REALLOC(ptr, size) realloc(ptr, size)
    #define STRDUP(str) strdup(str)
    #define FREE(ptr) free(ptr)
#endif
```

## 5. 高级配置
环境变量控制：
```bash
# 设置初始堆大小
export GC_INITIAL_HEAP_SIZE=10000000

# 启用并行垃圾回收
export GC_MARKERS=4

# 设置详细输出
export GC_PRINT_STATS=1
```

程序内配置：
```c
#include <gc.h>

int main() {
    // 在 GC_INIT() 之前设置
    GC_set_max_heap_size(1024 * 1024 * 100);  // 最大100MB
    GC_enable_incremental();  // 启用增量回收
    GC_set_finalize_on_demand(1);  // 按需运行终结器
    
    GC_INIT();
    
    // ... 程序代码 ...
}
```

## 6. 注意事项和限制
### 不能用于所有情况：
- 不适用于实时系统（回收时间不确定）
- 对于非常短命的程序可能增加开销

### 内存不是立即释放：
```c
void big_allocation() {
    char *huge = GC_malloc(1024 * 1024 * 500);  // 500MB
    // 函数返回后，内存不会立即释放
    // 要等到垃圾回收器运行时
}
```

### 可能漏掉的指针：
- GC通过扫描堆栈、全局变量、寄存器来查找指针
- 如果指针被隐藏在结构体字节中或经过加密，GC可能找不到

### C++注意事项：
```c++
// C++中可能需要重载 new/delete
void* operator new(size_t size) {
    return GC_malloc(size);
}

void operator delete(void* ptr) {
    // 什么也不做，GC会自动处理
}
```

## 7. 性能建议
```c
// 对于频繁分配的小对象，使用GC的快速分配
#define USE_GC_FAST_ALLOC

// 对于不包含指针的数据，使用GC_malloc_atomic（更快）
int *data = (int *)GC_malloc_atomic(1000 * sizeof(int));

// 对于长期存在的对象，考虑手动管理或使用uncollectable分配
```
